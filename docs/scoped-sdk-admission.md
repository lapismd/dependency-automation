# Inactive Desktop SDK admission

`config/scoped-admissions.json` has no live entries. The artifact capability
map is also empty. Source opt-in, artifact support and this separate operator
grant cannot promote a repository, remove an explicit hold or approve an audit.

The private Desktop graph can retain pending Core changes and unavailable AI,
Profile and development Tasks prerequisites while a future SDK patch has an
independent three-package public tool closure. Ordinary whole-repository
admission correctly holds that graph. A separately reviewed grant can select
only the exact root development SDK view after full current-source acceptance.

The grant binds raw source descriptor, canonical-policy bytes and immutable
projection shape. Its frozen prerequisite entries are exact package/path/type
tuples, limited to runtime AI/Profile and development Tasks. Both the source
descriptor/artifact capability and this grant are required. The source must
already be pilot, public, current, qualified and free of explicit operator holds.

Typed source registry findings authorize the bounded separation. Human hold
text never grants authority. Local paths, unknown/missing source coverage,
unknown registry absence evidence, stale/private input bytes, source CI,
identity, selected SDK prerequisites, audit and candidate ownership still fail
closed. Fresh target discovery reconstructs the same unpublished findings.

The full inventory graph is unchanged. The selected wave node retains deferred
updates, typed holds and publication waits under `scopedAdmission`, and human
summaries/PR messages distinguish this SDK-only view from full-repository
acceptance. Only the selected SDK tuple reaches existing canonical preparation,
regex generation and native frozen artifacts. Grant identity participates in
the durable operation; configuration and both sides of native generation
recheck it before copyback.

An unrelated PR cannot count as observing an uncertain write. Every retained
target needs matching owned branch-family, public candidate-head and actual
manifest/lock evidence. Unknown or empty historical targets still need explicit
recovery. This strengthens the common guard as well as the scoped path.

Activation remains a separate reviewed policy slice after actual Desktop source,
eight-archive audit, hosted projection/default health/callback acceptance and
operator decisions. Maintenance's optional scoped-evidence presentation must
also be qualified before a live grant. Neither this inactive implementation nor
historical SDK controls claims a new release or real current bot update.
