# Prepare bounded canonical dependency intake

The first opt-in profile updates one exact development dependency, its existing
workspace override and the mechanical pnpm lock closure. It preserves every
other manifest/workspace value and all other package identities, metadata and
dependency edges. The selected package may advance only by a forward patch;
its version and SHA512 integrity remain distinct from peer-context labels.
Unexpected changes require source review. This profile creates no new release
intent and does not change update scope, activation, channels or merge authority.

A consumer owns `.github/dependency-automation/canonical-intake.json`, two exact
canonical chapter paths, a named factual slot in each chapter and an ordinary
offline source check. The shared renderer stays in the coordinator; consumers
do not fetch or bootstrap its implementation during normal checks. The policy
is bounded JSON read from the admitted immutable default-branch revision, and
its digest/source SHA travel in the existing Renovate branch context.

The existing scripts-disabled frozen install and tooling guard precede
preparation. All input, baseline-slot, ownership and scope checks complete
before any chapter is written. Missing/changed policy, stale HEAD, non-regular
paths, ambiguous markers and manual text hold regeneration without overwrite.
Already prepared bytes are idempotent. Output is limited to the two policy
paths, each at most400 lines, and authored surrounding text is preserved.
No candidate module, package script, artifact or signing credential executes.

Discovery passes the policy into native Renovate configuration. Its exact two
paths extend post-upgrade file filters alongside the existing deterministic
Changeset path; broad spec globs remain absent. The shared command remains the
only permitted post-upgrade executable. Existing manual branch holds and
current-source/current-head qualification remain binding.

Notebook's first source profile covers Core development patches and its
existing override. Its two managed slots state actual version, supported peer
range, integrity and direct lock importers; they assert no unrun test result.
The Notebook domain adapter independently audits its catalog and source scope
using installed tools/local history, outside exempt specification commands.
Main's unchanged spec-first still requires both mapped chapters in the actual
change. The PR-only author/type exemption and every functional gate remain.

Qualification uses immutable public Notebook PR36 data: the original three
files produce two missing-map findings; the prepared two chapter outputs reduce
that count to zero through the actual validator. Native Renovate minimatch
retains both exact paths and excludes unrelated chapters. Fixtures exercise
real peer-context/hash renames, while arbitrary package integrity/importer or
settings mutations, stale source/policy, manual edits and unsafe paths reject.
No live bot branch or PR36 is changed by source verification.

Land the shared source and Notebook opt-in as separate reviewed changes. Until
both are deployed, missing preparation must fail Notebook's functional intake
check rather than qualify main. Do not merge an existing intake on its old
head: ordinary authorized reconciliation must prepare a fresh bot-owned head,
then complete all existing CI on that exact candidate and main. No rollout
variable or repository scope is changed by these source PRs.

For recovery, inspect the exact held input/reason and preserve manual changes.
A source owner can review a new policy or repair authored facts; never broaden
filters, append meaningless prose, forge qualification, weaken main spec-first
or rerun an uncertain remote write blindly. Other dependency families remain
outside this first profile.
